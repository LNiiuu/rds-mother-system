# P4 检索与上下文成本 / 质量对照实验报告

- 版本：v1.0
- 日期：2026-11-03
- 工作包：WP-2（P4）
- 结论摘要：**质量接近持平（MARS 96% vs 基线 92%），上下文载荷下降约 71%；单次会话总 Token 未显著下降（+13.5%，处于固定开销与样本噪声范围）**。按任务书 WP-2 验收门，Token 未显著下降时以质量/载荷改善与如实报告为准，不宣称 Token 节省。

## 1. 实验设计

| 项 | 内容 |
|---|---|
| 项目 | 合成项目 `rds-p4`（仅合成数据，未触碰星日晓/真实业务数据） |
| 记忆语料 | 32 条（approved 31 / proposed 1）：与任务相关的 approved 约 11 条（D1–D3 决策、F1–F4 事实、K1–K2 知识、S1 仅 R4 可见、T1 会议记录），N1 为 proposed；另 20 条为无关噪声 |
| 任务 | 6 个，覆盖 3 类：架构决策（P4-A1/A2，R1）、代码修改（P4-B1/B2，R2）、测试/审查（P4-C1/C2，R3） |
| 对照臂（base） | 现行流程：把项目全部记忆/会议记录不加过滤地粘贴给 Agent |
| 实验臂（mars） | MARS 检索 + 角色化 Context Compiler 生成 packet（budget 800，带查询关键词） |
| 运行方式 | 每个任务两臂各 1 次独立 subagent；同一模型、同一任务、同一输出格式；允许一次文件读取（读取对应 prompt），禁止其他工具 |
| 质量 rubric | 每任务 4 项预定义检查：`must` 关键词、`must_not` 关键词、2 个约束关键词；由 `scripts/phase4-score.js` 自动判定 |
| Usage 采集 | 从 DSH 会话 zstd 用 `ledger.parseSession` 复算 input/output/cacheRead/cacheWrite/total（真实 usage，非估算） |

prompt 与原始输出、评分、usage 均落盘在 `mars/experiments/p4/`：

- `prompts/base-<task>.txt`、`prompts/mars-<task>.txt`
- `results/<arm>-<task>.txt`（模型原始输出）
- `score.json`（逐项 rubric 与汇总）
- `usage.json`（逐会话真实 usage）
- `index.json`（任务、角色、packet_id、字节数）

## 2. 上下文载荷

| 指标 | base | mars | 变化 |
|---|---:|---:|---:|
| 6 任务 prompt 总字节 | 24,763 | 7,233 | **−70.8%** |
| 平均每任务字节 | 4,127 | 1,206 | −70.8% |
| 估算上下文 tokens（字节/4） | ≈1,032 | ≈302 | ≈−71% |

角色隔离核对：6 个 mars prompt 均不含 S1（role_scope=R4 的安全发现）与 N1（proposed 猜测）文本；base prompt 包含全部语料（对照组设计如此）。

## 3. 质量结果

| 任务 | 类别 | 角色 | base | mars |
|---|---|---|---:|---:|
| P4-A1 | 架构决策 | R1 | 3/4 | 3/4 |
| P4-A2 | 架构决策 | R1 | 4/4 | 4/4 |
| P4-B1 | 代码修改 | R2 | 4/4 | 4/4 |
| P4-B2 | 代码修改 | R2 | 4/4 | 4/4 |
| P4-C1 | 测试/审查 | R3 | 3/4 | 4/4 |
| P4-C2 | 测试/审查 | R3 | 4/4 | 4/4 |
| **合计** | | | **22/24（92%）** | **23/24（96%）** |

- JSON 可解析：两臂各 6/6。
- base 失分点：P4-A1 未显式写出“可重放/审计”双理由中的一项；P4-C1 漏掉 2 个约束关键词之一。
- mars 失分点：P4-A1 同类约束表述不足。
- 结论：在 32 条语料规模下，两臂质量接近；MARS 未因裁剪上下文而降低关键决策/约束覆盖。

## 4. 真实 Token / 会话成本

| 指标（6 次运行合计） | base | mars | 变化 |
|---|---:|---:|---:|
| input | 77,779 | 73,381 | −5.7% |
| output | 11,452 | 12,246 | +6.9% |
| cacheRead | 529,536 | 616,576 | +16.4% |
| total | 618,767 | 702,203 | +13.5% |
| 平均 total / 次 | 103,128 | 117,034 | +13.5% |

逐次 total（base）：P4-A1 132,676；P4-A2 87,134；P4-B1 87,567；P4-B2 87,529；P4-C1 88,603；P4-C2 135,258。
逐次 total（mars）：P4-A1 131,464；P4-A2 86,604；P4-B1 130,390；P4-B2 87,525；P4-C1 134,432；P4-C2 131,788。

解读与限制：

1. 单次会话总 Token 主要由固定系统提示/工具定义/缓存前缀构成，本实验上下文载荷差异（约 700 tokens）只占 0.7% 左右，**不足以证明总 Token 下降**；+13.5% 属运行间波动（同一任务两臂相差可达 5 万），不能作为“MARS 更贵”的结论。
2. `cacheRead` 是复用前缀的计费口径，不等于“无效 Token”，任务书明确不得单独作优化标准。
3. 成本收益需要在长会话/多任务/大语料下测量；本实验只证明“角色过滤与检索可用、质量不降、载荷显著减小”。

## 5. 偏差与异常

- `usage.json` 原始扫描发现一个异常会话（`session-ede72e66-…`，total 5.33 亿），为同一 marker 的合并/续跑会话，已按“每个任务每臂取最小合理会话（≤100 万）”规则排除并保留记录；P4-B1/mars 采用 130,390。
- 每个任务每臂仅 1 次运行（n=1），只覆盖 6 个任务；不做冷/热启动分离。
- 评分由 R0 用预定义关键词自动判定，非盲评；R5–R7 未参与。
- 语料为合成数据，噪声为人工构造，规模小于真实项目。

## 6. 复现

```powershell
cd D:\M1\mars
node scripts/phase4-build.js    # 重建 rds-p4 语料与两臂 prompt
# 逐任务运行 subagent（读取 prompts/<arm>-<task>.txt，只输出 JSON）
node scripts/phase4-score.js    # 质量评分
node scripts/phase4-usage.js    # 真实 usage 汇总
```

## 7. 结论与建议

- P4 实验框架可重复使用，质量与载荷指标均落盘可审计。
- 当前证据支持：**MARS 上下文载荷约 −71%，质量 96% vs 92%（样本内），单次总 Token 无显著变化**。
- 建议下一轮（非本轮范围）：扩大语料到 200+ 条、每臂 ≥3 次、盲评、按任务类别分别报告；在长会话场景验证累计节省。
