# WF5 Git 变更审查

## 目的

在变更完成与提交之间建立可复用的审查闸门：先审查、再准入、最后按授权级别执行动作。WF5 作为 WF1/WF3/WF4 的出口闸门，位于 G3（实现门）之后、G4（审查门）之前。

## 角色

| 角色 | 职责 |
|---|---|
| R0 | 签发 `git-authorization.json`、调度、核对报告 |
| R2 | 实现变更并提供自测证据（不得自行暂存/提交） |
| R3 | 运行质量命令，产出退出码与证据 |
| R4 | 独立复核报告与 diff，给出 G4 准入 |
| R7 | 仅执行已批准的提交/推送（L2/L3；本轮不涉及） |

## 流程

1. **授权**（R0）：新建机读授权，写明 `taskId`/`level`/`allowedPaths`/`deleteAllowed`/`approvalId`；默认 L0，禁止沿用历史授权。
2. **基线**（R3）：记录 HEAD、分支、暂存区摘要、工作区清单摘要。
3. **审查**（R3 执行工具，R4 复核）：
   - 范围：变更路径必须匹配 `allowedPaths`；删除需 `deleteAllowed`；路径黑名单命中即阻断。
   - 完整 diff：已暂存 + 未暂存 + 未跟踪；未跟踪文件必须单独读取全文。
   - 文件分类：二进制、超大文件、不可读/不可解析 → 显式阻断。
   - 敏感扫描：外置规则（路径 → 正则 → 熵 → 个人数据），命中只留掩码。
   - 编码：CRLF/BOM/末尾空行 → 记录，判 `PARTIAL`。
4. **报告**（工具自动）：JSON + Markdown + diff 工件；Schema 校验通过才算完成。
5. **准入**（R4）：核对报告与任务卡一致；非 PASS 不得进入提交。
6. **动作**（R7）：仅按授权级别执行；L0 无动作。

## 门

- G4 准入条件：报告 `verdict=PASS`（或经批准登记例外后的 `PARTIAL`）+ 证据齐全 + 范围一致。
- G4 不通过：回 R2 修复后重审，同任务默认 ≤2 轮。

## 失败分支

| 情况 | 处理 |
|---|---|
| 越界文件/未授权删除 | `FAIL`，停止，报告 R0 |
| 高置信秘密命中 | `FAIL`，掩码上报，凭据不得进入聊天/日志 |
| 二进制/超大/不可读 | `BLOCKED`，需例外审批 |
| 仅编码格式 | `PARTIAL`，记录；需要时单独建“编码规范化”任务 |
| 审查后工作区被改动 | 重算基线，报告失效，必须重审 |
| 授权缺失/过期/级别不符 | 立即停止，不执行任何动作 |

## 证据

- 报告：`docs/checks/git-review/run-<时间>/report.json` + `report.md` + `diff.patch` + `commands.log`
- 证据编号：`EV-YYYYMMDD-NNN`；强度按 E1–E4 标注。
- 报告不覆盖历史；同一变更的多次审查各自成目录。

## G1 限制

G1 只实现 L0 与基础审查；完整指纹、文档事实核对、历史完整性检查归 G2；远端核验与自动推送归 G3。
