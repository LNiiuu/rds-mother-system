# 权限规则（母体系）

## 1. 真相

- 系统级边界只有两层：**DSH 沙箱**（workspace-write / danger-full-access）与**审批策略**（ask）。二者是会话级/进程级，**不是 per-Agent ACL**。
- 角色卡的"只读/仅 inScope 可写"是**提示词级约定**；可被提示词覆盖，不可作为安全边界宣称。
- 若未来部署声明了 tool policy，才存在成员级工具白名单；届时以配置为准并复验。

## 2. 角色写权限

| 角色 | 默认 | 可写范围 |
|---|---|---|
| R0 总控 | 管理资料可写 | 任务卡、进度账、证据目录；业务代码默认只读 |
| R1 架构 | 只读 | 仅任务卡 inScope 内的设计文档 |
| R2 实现 | 只读 | 仅任务卡 inScope；禁止越界 |
| R3 验证 | 只读 | 仅测试证据目录 |
| R4 审查 | 只读 | 审查报告（证据目录） |
| R5 研究 | 只读 | 研究草稿目录（任务卡指定） |
| R6 逆向/安全 | 只读 | 分析证据目录 |
| R7 发布/运维 | 只读 | 发布记录 |

## 3. 硬规则

1. 实现任务必须在任务卡写明 `inScope`；未写明不得开工。
2. 禁止 `git commit/push/reset/clean` 等写操作，除非任务卡明确授权且审批通过。
3. 禁止访问与本任务无关的项目目录；禁止把其他项目文件读入本任务上下文。
4. 证据只写证据目录，不改业务文件。
5. 越界检测：交付前执行只读 `git status` 对比 inScope；无 git 时用文件哈希清单。
6. 需要提权、改安全策略、连真机、读真实数据、配置凭据时：**停下，单独申请**。
