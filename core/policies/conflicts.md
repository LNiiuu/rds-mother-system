# 冲突与并发规则

## 类型与处理

| 类型 | 处理 |
|---|---|
| 结论冲突（研究/评审） | 不强行统一；列双方原文与分歧根因，交 R4 裁决；裁决记证据 |
| 文件并发写 | **禁止**两个任务同时写同一文件；任务卡 inScope 不得重叠；发现重叠立即停并报告 |
| 任务状态冲突 | 以任务卡 + 证据为准；状态不一致时 R0 冻结该任务，人工确认后恢复 |
| 权限/边界冲突 | 立即停；按 `permissions.md` 升级审批 |

## 单写者规则

- 任一文件同一时刻只有一个写者（任务卡声明）。
- 写前检查：文件是否被其他进行中任务的 inScope 覆盖；是则停。
- 冲突不可自动合并时，保留双方产物，不删不改，交用户裁决。
