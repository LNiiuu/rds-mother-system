# 任务管理规则

## 状态机

`待派发 → 进行中 → 待审查 → 通过 / 打回 → 已归档`

- 只有总控（R0）能触发"待审查"。
- 打回必须带缺陷单（编号、严重级、复现步骤、期望）；同一任务默认最多返工 2 轮，第 3 轮升级用户。
- 中断（掉线/超时/上下文耗尽）由 R0 重新派发，**不沿用旧 attempt**；旧 attempt 的产出只作为证据，不作为结果。

## 派发规则

1. 一卡一人；依赖显式声明。
2. 并发上限：同刻 ≤8 个子 Agent；研究类 ≤6。
3. 委派一层，成员不再向下委派。
4. 派发前核对：任务卡完整（目标/inScope/验收/证据要求）、授权路径存在、验证命令可执行。
5. 并行仅限真独立任务；有依赖用依赖关系，不轮询。

## 审查规则

- 实现必须由独立审查角色（R4）复核；审查者不参与实现。
- 审查只信证据：命令、输出、哈希、时间戳；不采信"我已完成"。
- 审查通过才进入用户验收。

## 停止条件（必须暂停）

装插件/改权限、提权、碰真实数据或真实设备、高风险命令、能力不足、发现越界修改。
