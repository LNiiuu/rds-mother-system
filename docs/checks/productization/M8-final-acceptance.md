## 1. 五个必答问题

### 1.1 当前 RDS/MARS 是否已经达到最小可用标准？

**是，限 Windows + 本地单机 + 单项目。**

| MVP 要素 | 状态 |
|---|---|
| 能安装 | 是（本地 tgz / 源码树） |
| 能初始化 | 是（`init` + `init-dev`，默认不破坏已有身份） |
| 能配置 | 是（环境变量 + 默认路径；`doctor` 11 项） |
| 能写入与审批 | 是（双身份、自审拒绝、状态机） |
| 能编译与读取上下文 | 是（JSON / Markdown，可携带任务正文） |
| 能追溯 | 是（audit 自动记录；备份/校验/恢复可用） |
| 有自动化测试 | 是（**210**，门禁要求 fail=0 skip=0） |
| 有文档 | 是（install / quickstart / maintainer-guide / PROJECT-MAP） |

**不构成的**：它不是多 Agent 运行时、不是任务执行器、不是自动验收系统。
R0–R7 里只有 R0/R4 有代码强制力，其余是约定。

### 1.2 用户能否在干净环境中独立安装和使用？

**能，Windows 已实测；Linux/macOS 未跑 M8 改动。**

证据：

- 干净克隆 `c0fe381`：373 文件、`dirty=0`、210/210、BASELINE PASS、PACK PASS、SMOKE PASS。
- 临时前缀安装发行包：`rds --version` = 0.1.0，`doctor` 11 项全过（warn=0）。
- 从零跑完：init → init-dev → 重复 init-dev 被拒 → `--add` 第二身份 → 旧 token 仍可用 →
  register → put → review → compile（Markdown）→ audit，全部成功。
- 安装后的 Markdown 包 **1 067 B**，任务正文在包内。

限制：干净环境验证只在 Windows 做；Linux/macOS 的 M8 改动没有 CI 结果（见 §4）。

### 1.3 核心流程是否真正闭环？

**数据链路闭环；任务执行链路只闭合了一半。**

| 链路 | 状态 |
|---|---|
| 任务 → 决策 → 审批 → 编译 → 审计 | **代码闭环**（每一步都有强制校验） |
| 编译 → Agent 执行 → 验收 | **人工闭环**（没有强制读包、没有执行器、没有验收层） |
| 规划 → 派角色 | **可选且不稳定**（分类随措辞漂移） |

所以准确表述是：**MARS 能保证「进入上下文的决策是经过审批的」，不能保证「任务被正确执行」。**
把 R1–R7 说成「系统已具备多角色隔离」是不成立的。

### 1.5 还有哪些问题阻止正式发布？

按严重度：

| # | 问题 | 为什么阻止发布 | 建议 |
|---|---|---|---|
| 1 | **M8 没有 CI 结果** | 只在本地与干净克隆验证；CI 需 push 触发，本阶段未授权 | 授权一次 push，看 7 个 job |
| 2 | **规划分类不稳定** | 「实现…并补测试」被判为 `verification`，会派错角色 | 记录命中关键词，允许 `--class` 覆盖 |
| 3 | **角色/工作流无强制力** | 文档若暗示「R1–R7 已隔离」会误导使用者 | 文档统一口径：R0/R4 强制，其余约定 |
| 4 | **无自动 token 账本** | 系统不知道一次编译省了多少，价值无法自证 | `feedback` 自动取数 |
| 5 | **未发布 npm** | 只能本地路径安装 | 发布前先补 LICENSE/仓库元数据（未做） |
| 6 | **Linux/macOS 未跑 M8** | M8 改了 CLI 与编译器，跨平台未复验 | 授权 CI 后自然覆盖 |
| 7 | `principal revoke/list` 缺失 | 身份撤销要手工改文件 | 不阻塞 MVP，列入下一阶段 |
| 8 | 包内分节未去重 | 重复记忆会重复出现 | 低优先 |

## 5. 已知限制（诚实清单）

1. 单机、单项目、本地文件系统；没有并发与多租户验证。
2. 角色 R1–R3、R5–R7 是 Markdown 约定，不是运行时隔离。
3. 规划器是关键词规则，分类会漂移；没有人工覆盖参数。
4. 包内 `missing` 的 blocking 标记是提示，不阻断编译。
5. Markdown 包不含 manifest；需要片段哈希时用 JSON。
6. 分节内容未做跨记忆去重。
7. `rds principal revoke/list`、`upgrade`、`uninstall` 未实现。
8. 未发布 npm；未加 LICENSE / repository 字段。
9. M8 只在 Windows 实测；Linux/macOS 待 CI。
10. 没有自动 token 账本，MARS 的价值仍无法在运行时自证。

## 6. 建议的下一步

1. **先授权一次 push**，让 7 个 job 覆盖 M8 改动——这是唯一未闭环的验收项。
2. 再做 **P1-1 自动 token 账本**（`orchestrate feedback` 自动取数），否则「省不省」永远靠人算。
3. 之后才考虑规划器分类与角色强制力；在拿到真实使用数据前，不建议扩角色或加 AI 接入。

**结论**：RDS/MARS 现在是一个**能在干净 Windows 环境装起来、跑通、
默认不丢身份、上下文包能自足且更便宜**的最小可用工具。
它还不是一个「多 Agent 研发平台」，也不应该被这样描述。
