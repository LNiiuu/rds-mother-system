## 1. 方法（为什么这样比）

```
旧版代码：git archive ada7848（M7 封版点）→ 解到隔离目录 → 用同一份 DB 副本编译
新版代码：当前工作区（M8）→ 用另一份同源 DB 副本编译
```

- 两份 DB 都是 `D:\M7-lab\mars-data` 的副本，项目 `xsum`、8 条已批准记忆、同一 R0 身份。
- 因此两边的 `tokens_estimated` 都是 **344**，内容完全一致；差异只来自载体。
- 编译命令除新增参数外一致：`--project xsum --task XSUM-1 --role R0 --budget 4000`。
- 耗时各跑 5 次取中位。

**没有混用 M7 的原始数字**：M7 那次是 6 条记忆、240 tokens、10 105 B；
本轮为了让「前后」可比，**重新用旧代码跑了同一份 8 条记忆的状态**，得到 11 101 B / 344 tokens。
M7 的原始记录仍然保留在 `docs/checks/m7/`，两组数字不放在一起算。

### 2.1 真实 provider token 测量

字节数会被 JSON 标点放大，所以另做了一次真实测量：
在同一会话里连续读两个文件，取相邻模型调用的 `prompt_tokens` 差值（数据来自会话记录的 `rawUsage`）。

| 文件 | 字节 | 实测 prompt tokens | 相对旧版 |
|---|---|---|---|
| `packet-old.json` | 11 101 | **6 381** | — |
| `packet-new.md` | 6 589 | **2 786** | **−56.3%** |

- 字节降幅是 −40.6%，token 降幅是 −56.3%——**JSON 的引号、括号、哈希比中文正文更难分词**，
  所以字节数其实低估了旧包的代价。
- 新 MD 还额外携带了 4 231 B 的任务正文，信息更多、token 更少。
- 口径说明：单样本；差值包含 Read 工具的行号与包装；不是供应商账单对账，但确实是运行时上报的
  `prompt_tokens`，不是估算。

## 3. 没有改善的地方（如实）

| 项 | 现状 | 说明 |
|---|---|---|
| 带任务正文的 JSON | 8 404 B（`--no-manifest`） | 比旧版无正文的 8 074 B 大，因为它多带了 4 231 B 正文。**这是信息量增加，不是退化**；与「旧包 + 原文」15 332 B 比仍小 45% |
| Markdown 的可追溯性 | 无 manifest | 分节正文与来源注释在，但片段哈希/清单只在 DB 与 JSON 输出里。需要程序化追溯时用 JSON |
| 包内 `missing` | 仍会提示 blocking evidence | R0 角色配置要求证据引用；这是角色语义，不是包格式问题。本轮未改 |
| 分节内容去重 | 未做 | 如果两条记忆内容重复，包内仍会出现两次。本轮只消除了「同一内容在 packet/budget 各印一遍」的结构重复 |

## 4. 结论

1. **同内容的 JSON 载体缩小 27.3%**，重复内容占比从 22.7% 降到 0。
2. **带任务正文的 Markdown 让「读包」替代「读包 + 读原文」**，读取字节 −57.0%，
   实测 token −56.3%。
3. 任务正文完整，不截断、不改写。
4. 编译耗时不退化。
5. 兼容性代价明确：`--out` 的 `budget.sections` 被移除；需要它的调用方改用 `packet.sections`。

这回答了 M7 提出的三个问题，但没有回答「MARS 是否因此更有价值」——
那需要按 M7-3 §5 的建议，用新执行者与交叉顺序重跑一次 A/B。本轮不做这个推断。
