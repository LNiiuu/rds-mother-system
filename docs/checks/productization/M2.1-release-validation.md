# M2.1 发行包验收

> 方法与 M1 相同，但本轮在两个 Node 版本上各做一遍，并对内容断言做了逐项核对。
> 所有操作在临时目录完成，不使用仓库内的既有数据库与真实 `principals.json`。

---

## 1. 构建

| 项 | Node 22.22.2 | Node 24.22.2 |
|---|---|---|
| 打包命令 | `npm pack` | `npm pack`（npm 11.19.1） |
| tarball | `rds-mother-system-0.1.0.tgz` | 同 |
| 文件数 | 87 | 87 |
| 体积 | 77,362 B | 77,362 B |

两个 Node 版本产出的 tarball **字节数一致**，说明打包结果不受运行时版本影响。

## 2. 内容检查（`tooling/pack-check.mjs`）

```
PACK PASS  必需文件齐全，禁止项 0 命中
```

### 必需项（17 项，缺一即失败）

`package.json`、`VERSION`、`LICENSE`、`bin/rds.mjs`、`bin/doctor.mjs`、`bin/validate.mjs`、
`docs/install.md`、`mars/src/cli.js`、`mars/src/ledger.js`、
`mars/contracts/{memory,context-packet,manifest,ledger,role-routing}.schema.json`、`mars/config/role-routing.json`、`mars/config/principals.example.json`、`core/templates/project.yaml`

> `mars/contracts/*.json` 这 5 项是 M1 阶段实测发现的漏打包项（缺了会让 `put` 直接 ENOENT），
> 现在已固化为断言。

### 禁止项（10 类规则，命中即失败）

| 规则 | 原因 |
|---|---|
| `mars/tests/`、`tests/` | 测试不随包分发 |
| `docs/history/`、`docs/checks/` | 历史材料与检查记录不随包分发 |
| `mars/experiments/`、`mars/var/` | 实验与运行时数据不随包分发 |
| `principals.json` | 身份文件绝不能进包 |
| `toolchain.local.json` | 本机工具链配置不随包分发 |
| `*.db` / `*.db-wal` / `*.db-shm` | 数据库 |
| `*.zstd` / `*.jsonl` | 会话样本 |

## 4. 安装后的自检差异

| 环境 | `paths:code` | `paths:docs` | 说明 |
|---|---|---|---|
| 从 tarball 安装 | `ok`（41 文件，0 命中） | `ok` | 包内不含 `docs/history` 等历史材料 |
| 源码仓库 | `ok`（102 文件，0 命中） | `warn`（11 文件） | 历史证据记录含本机路径，属 M5 清理范围 |

两类警告的语义不同：安装包的 `ok` 才是用户看到的；仓库内的 `warn` 是历史材料。

## 6. 结论

发行包在 **Windows × Node 22 / Node 24** 两个运行时上均通过构建、内容断言、干净安装与七步核心流程。
