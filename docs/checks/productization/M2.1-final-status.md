## 7. 是否具备进入 M3 的条件

**代码层面：具备。** M1/M2 的落点清晰，测试去环境化完成，门禁可信，发行包可控。

**质量基线层面：不具备完整条件。** M3 是解耦重构（搬 `ledger` 的 DSH 解析、拆宿主适配层），
这类改动的风险恰恰在"看不出来的地方坏掉"，必须有双平台 CI 守门。当前只有单平台本地证据。

建议的最小前置动作：

1. 在网络可达的环境执行一次 `git push origin main`（当前 ahead 5，快进即可）；
2. 确认四组 job 结果，把结论回填到 `M2.1-ci-validation-report.md`；
3. 若 Ubuntu 失败，按 §6 的排查顺序修复后再进 M3。

如果网络短期无法恢复，也可以进 M3，但必须接受「重构期间只能靠 Windows 单平台验证」，
并且每次改动后手工跑 `npm run verify && bash tooling/ci-smoke.sh`。
