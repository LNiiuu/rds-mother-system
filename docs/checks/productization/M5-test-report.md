### 2.1 为什么给「帮助」写 12 个用例

因为它修的是一个 **S1 数据丢失缺陷**：`rds init-dev --help` 此前会生成身份并**整个覆盖** `principals.json`（实测把 6 个 principal 覆盖成 1 个）。

12 个用例分三组，每组都对应一个真实发生过的错误行为：

| 组 | 用例 | 回归的行为 |
|---|---|---|
| 覆盖 | 每个已知命令都有帮助条目 | 新增子命令忘了写帮助 |
| 覆盖 | 每个帮助条目都对应已知命令 | 删命令后留下死条目 |
| 覆盖 | 22 个命令 `--help` 退出 0 且以「用法: rds」开头 | 报 `TOKEN_MISSING`（exit 3）或「网关默认禁用」（exit 5） |
| 覆盖 | `-h` 与 `--help` 输出一致 | 别名分叉 |
| 无副作用 | `init --help` 不创建数据库 | 想看说明结果建了库 |
| 无副作用 | `init-dev --help` 不改写已有身份文件 | **S1**：想看说明结果丢了身份 |
| 无副作用 | 身份文件缺失时 10 个命令 `--help` 不报认证错误 | 把帮助请求诊断成凭证问题 |
| 无副作用 | `mcp --help` 不返回「网关默认禁用」 | 同上 |
| 一致性 | `rds help <cmd>` 与 `rds <cmd> --help` 逐字节相同 | 两个入口各写一份文本 |
| 一致性 | 顶层帮助列出全部命令与 6 个公共选项 | 新命令不出现在总览 |
| 一致性 | 未知命令的 `--help` 报未知命令 | 错误诊断错位 |
| 一致性 | 帮助文本不含本机绝对路径 | 可移植 |

### 2.2 为什么给「路径」写 4 个用例

`ledger` 输出的 `sessions[].path` 是绝对路径。这既是设计意图（能直接打开原文件），也是已知限制（不适合提交到版本库）。

本轮**不改**它（改 JSON 输出格式需授权），但把现状固定成契约：任何「顺手改成相对路径」的改动会立刻变红。

四个断言：绝对路径、能解析到真实文件、相对输入仍输出绝对、JSON 与 CSV 的 path 一致，外加「ledger 不创建数据库」。

### 2.3 为什么给「文档检查器」写 7 个用例

如果它永远返回 0，它就是个装饰品。

7 个用例覆盖：全可达退出 0、真实断链退出 1 并指出行号、代码块里的伪链接不算断链、http(s)/锚点/占位符不算断链、带锚点的链接按文件部分校验、`--json` 输出结构、本仓库当前通过。
