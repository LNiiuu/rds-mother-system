## 1. 实现的策略

| 策略 | 状态 | 具体行为 |
|---|---|---|
| A 去重 | **已实现** | 内容哈希相同 → 只留一个，其余来源并入保留项 |
| B 重复日志折叠 | **已实现** | 连续且完全相同的行 ≥3 才折叠为 `…（重复 N 次）` |
| C 结构化摘要 | **部分** | 只做「交接摘要」：字段来自任务记录，不生成语义；**不做自动正文摘要** |
| D 历史归档 | **已实现** | L3 分节原文移入 `compressions`，包内只留恢复指引（<40 tokens 不归档） |
| E 按需加载 | **已实现** | 归档 + `context restore --compression <id>`（SHA-256 校验） |

## 2. 触发器与安全规则

- 触发条件：模型使用率 ≥0.85（HIGH/CRITICAL/EXCEEDED）**或**任务预算使用率 ≥0.85。
- L0（`task`、`prohibitions`）任何情况下不修改；改了就记 `L0_MODIFIED` 并回退原文。
- 压缩后 token 不减少 → 记 `NO_GAIN`，回退原文，不假装成功。
- 原文与压缩结果都落库，`original_hash` 恢复时校验；篡改则拒绝返回。
- 压缩记录含策略、前后 token、校验状态、原始分节 JSON。

## 5. 结论

M10 交付了一个**可解释、可回退、可恢复**的确定性压缩层：
它在超预算时确实降 token，且不会动 L0、不会吞掉无法安全压缩的内容。
但它不是「智能摘要」——任何把它描述成 AI 压缩的说法都不成立。
