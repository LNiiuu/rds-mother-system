# M3 风险与回滚方案

**基线**：`51a562e`。M3-1 本身不改代码，本文的风险针对 **B0–B5 六批实施**。

---

## 2. 回滚粒度

### 2.1 三级回滚

| 级别 | 触发 | 动作 | 恢复时间 |
|---|---|---|---|
| L1 单批回滚 | 某批验收不过，且原因在本批 | `git revert <batch-commit>` | 分钟级 |
| L2 阶段回滚 | 连续两批失败，怀疑设计前提有错 | 回到 `m3-b0` tag 前的基线（`51a562e`），保留设计文档 | 分钟级 |
| L3 环境回滚 | 工作区被污染 / 原有工作有风险 | 从备份恢复（见 2.3） | 十分钟级 |

### 2.2 每批的 tag 与回滚命令

```
m3-b0  ← B0 完成后打
m3-b1  ← B1 完成后打
m3-b2
m3-b3
m3-b4
m3-b5
```

回滚第 N 批：

```bash
git revert --no-edit m3-b<n>            # 保留历史，生成反向提交
node tooling/test-gate.mjs              # 必须回到 88/88/0/0
node bin/rds.mjs doctor                 # 必须 0 fail
bash tooling/ci-smoke.sh                # 必须 SMOKE OK
```

**禁止**用 `git reset --hard` / `git clean -fd` / 覆盖式 checkout 回滚 —— 会丢掉工作区里 51 项原有工作。
（这条与 M1 任务书 §1.3 的禁令一致，M3 继续适用。）

### 2.3 备份点

| 备份 | 位置 | 内容 | 何时用 |
|---|---|---|---|
| M1 开工前全量 | 仓库外备份目录 `M1-backup-20261108-162614` | 71 项未提交工作 + 当时 HEAD | L3 |
| 每批 tag | 仓库内 | 代码快照 | L1 / L2 |
| 数据库 | `mars/var/mars.db`（不入库） | 运行时数据 | **M3 不改 schema，正常情况下无需恢复** |

M3 全程**不做数据库迁移**，因此"数据回滚"这一最危险的场景在设计上被排除了。
若某批意外改动了 `SCHEMA_VERSION` 或 DDL，B5-2/B5-3 会立刻失败 —— 这是硬红线。

## 3. 各批的具体回滚关注点

| 批 | 回滚时必须额外确认 |
|---|---|
| B0 | 错误码映射回到"两份白名单"后，旧网关的 6 个码会再次退化为 `INTERNAL_ERROR`；这是**已知退化**，不是新故障 |
| B1 | 组合根删除后，`store/compiler/manifest` 是否恢复为模块级读盘；`pack-check` 是否会因 `ports/` 目录残留而误报（需同时删目录） |
| B2 | 配置快照删除后，`MARS_ROUTING` 是否恢复"每次调用读环境变量"；长驻 MCP 的行为差异要一并回退 |
| B3 | **契约回滚要单独确认**：`const` 恢复后，若期间已产生 `source_kind != 'dsh-session'` 的账本，会校验失败。M3 期间不应产生此类数据；若已产生，需保留 `pattern` 版本并升 `contract_version` |
| B4 | **最需要谨慎**：若已执行过 `--yes`，回滚代码不会恢复被改的外部注册表。必须用 `mars/var/mcp/registry-backup-*.json` 手工还原，并通知宿主重启 |
| B5 | 转发壳删除后，9 个依赖方的 require 会指向不存在的 `db.js`；必须同时恢复 `db.js` 或保留壳 |

## 4. 停止条件（必须停下来问用户，不得自行决定）

1. 发现原有 51 项工作有任何丢失、覆盖或被提交的迹象；
2. 需要改数据库 schema 或执行数据迁移才能继续；
3. 需要降低任何既有测试标准（删断言、加 skip、`continue-on-error`）；
4. 需要写外部产品的配置文件，而备份无法确认可还原；
5. 契约变更超出"放宽 `source` / `source_kind`"这一条，例如需要删除字段或改字段语义；
6. CI 连续两轮在同一处失败且本地无法复现；
7. 出现"必须先修的安全问题"且不在本方案范围内（见 §6）。

普通的测试失败、路径差异、依赖缺失**不属于**停止条件 —— 应自行定位并继续。

## 5. 不可逆操作清单（M3 期间一律不做）

| 操作 | 为什么不可逆 |
|---|---|
| `git push --force` / `rebase` 覆盖远程 | 会改写他人的提交历史 |
| 删除 `mars/var/mars.db` | 运行时数据无副本 |
| 对真实用户会话目录执行写入/移动 | 影响用户数据 |
| 对外部产品注册表执行"先删后建" | 中途失败会留下半成品配置 |
| 改写 `docs/history/**` 与 `mars/docs/**` 的历史记录 | 等于篡改证据（M5 单独处理） |
| 在未备份的情况下执行 `--yes` 类破坏性参数 | 同 B4 |

## 6. 独立安全发现（不在 M3 范围，需用户知晓）

调查中发现两处安全问题。**都不阻塞 M3**，但都不应沉默：

### S-01 外部注册表写入无格式协商（= H-04，S1）

`mars/scripts/mars-mcp-disable.ps1:6,43-45` 直接读取并整文件重写另一产品的私有注册表。
风险：对方升级格式后，本脚本会静默丢弃未知字段。

- **M3 内处理**：B4 用 `HostRegistry` 端口 + 原子写 + 未知格式拒写收口。
- **在此之前的使用建议**：只用默认 dry-run（不加 `-Yes`），或在执行前手工复制一份 `registry.json`。

### S-02 审计主体可伪装（= H-07，S2）

`mars/src/cli.js:124` 把 `principal_id` 写成字面量 `'cli'`，而 `authz.js:6` 又声明了 `ledger.read` 动作却从不校验。
后果：`audit` 表里存在"看起来像已认证主体、实际未认证"的记录。

- **影响面**：仅 `ledger` 子命令（只读会话文件 + 写一条审计，无越权写入）。
- **M3 内处理**：B3 把 `principal_id` 改为 `'local'` 并移除未执行的 `ledger.read` 动作。
- **在此之前**：不要把 `audit` 表当作合规证据使用；`ledger` 相关的审计行不可作为"谁读过"的凭据。

其余 12 个耦合点不含安全性质，逐条见 `coupling-map.md`。

## 7. 回滚演练要求

每批完成后，**至少做一次回滚演练**（不推送，纯本地）：

```bash
git revert --no-edit m3-b<n>
npm run verify                      # 应回到上一批的绿
git revert --no-edit HEAD           # 撤销撤销，回到本批
npm run verify                      # 应回到本批的绿
```

只演练不验证的回滚方案等于没有方案。演练结果记入该批的 commit message 末尾一行：
`rollback-rehearsal: pass (revert → verify ok → revert revert → verify ok)`。
